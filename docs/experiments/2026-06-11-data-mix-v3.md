# Experiment: data-mix expansion — `devalade/whisper-large-v3-yoruba-v3`

**Date:** 2026-06-11 (trained 2026-06-10 22:13 UTC, evaluated 2026-06-11 01:38 UTC; flipped as M1 default 2026-06-12)
**Goal:** Replace v2's single-speaker Hidi-agili corpus with a demographically balanced multi-source mix (Hidi-agili + chukypedro by gender/age + FLEURS yo_ng train) to break the single-speaker overfit diagnosed in v2. Hypothesis: FLEURS WER drops ≥ 5 pts vs v2 on the same epoch budget by varying only the data axis.
**Outcome:** ✅ **Shipped and flipped as M1 default 2026-06-12.** v3 beats v2 by 4.56 pts on FLEURS (66.09% → 61.53%, cloud CUDA fp16) and 4.83 pts (68.54% → 63.71%, local MPS fp32 — see "Local MPS replication" below). Confirms the data-diversity hypothesis directionally and protocol-independently; lands 1.5 pts short of the explicit ≤ 60% target but is the best M1 backend by a clear margin, so it ships now and the gap is parked as future work.

### Data mix (`config.FT_DATA_MIX` as of this trial)

`chukypedro/clean_yoruba_dataset` is partitioned into 14 parquet shards across 6 gender × age demographics, confirmed via `scripts/inspect_dataset.py` (2026-06-10). The `speaker_id` column is unreliable (every shard labels its rows `speaker_id=1`), so each demographic shard is treated as a separable voice profile.

| Source | Rows | Role |
|---|---|---|
| `Hidi-agili/yoruba_tts_dataset` | 5,000 | Anchor — prevents catastrophic forgetting of v2's TTS distribution |
| `chukypedro` male_18-29 | 2,000 | Diversity |
| `chukypedro` male_30-over | 2,000 | Diversity |
| `chukypedro` female_18-29 | 2,000 | Diversity |
| `chukypedro` female_30-over | 2,000 | Diversity |
| `chukypedro` male_6-17 | all (~600) | Rare-demographic preservation |
| `chukypedro` female_6-17 | all (~700) | Rare-demographic preservation |
| `google/fleurs` yo_ng train (`raw_transcription`) | 2,500 | Multi-speaker read speech, in-distribution with FLEURS eval |

License caveat on `chukypedro/clean_yoruba_dataset`: dataset card was empty at the time of training; no documented license. To be flagged explicitly in `methodology.md` for the writeup.

Common Voice yo was dropped — chukypedro's demographic coverage was broader and not gated. Revisit if a future trial needs more spontaneous-speech diversity.

## Results

### Training curve

| Epoch | Train loss | Eval loss | Eval WER (in-mix held-out, 5%) |
|---|---|---|---|
| 1 | 1.437 (end) | 1.4404 | 83.07% |
| 2 | 1.226 (end) | 1.2238 | 63.21% |
| 3 | 1.181 (end) | **1.1812** | **59.22%** |

Per-step training-loss trajectory: 4.37 (step 25 / mid-warmup) → 2.71 (step 227 / post-warmup) → 1.44 (epoch 1 end) → 1.22 (epoch 2 end) → 1.18 (epoch 3 end).

Eval loss tracked training loss the whole way → no overfit. The catastrophic-interference dip in epoch 1 (warm-started v2 confused by 7 new distributions at once) resolved cleanly in epoch 2 with a 20-point WER drop, then tightened by ~4 pts in the LR-decay tail.

### Thesis-grade FLEURS yo_ng test (N=200, beams=5)

All four models scored on the same protocol — first apples-to-apples comparison for this thesis. Per-sample reference/hypothesis pairs in [`logs/wer_hf_v{1,2,3}.jsonl`](../../logs/).

| Model | Aggregate WER | Δ vs v1 | Δ vs v2 |
|---|---|---|---|
| `openai/whisper-large-v3` (zero-shot baseline) | 88.6% (prior measurement) | — | — |
| **v1** `devalade/whisper-large-v3-yoruba` | **65.92%** | — | — |
| **v2** `devalade/whisper-large-v3-yoruba-v2` | **66.09%** | +0.17 (worse) | — |
| **v3 (this run)** `devalade/whisper-large-v3-yoruba-v3` | **61.53%** | **−4.39** | **−4.56** |

- v1 ↔ v2 → confirms the single-speaker overfit diagnosis: v2's extra epochs on Hidi-agili gave **zero** generalization benefit on FLEURS.
- v2 → v3 → 4.56 pt FLEURS drop on the same epoch budget and same LoRA recipe, varying only the data mix. Directionally validates the hypothesis.
- v3 vs trial gate (≤ 60% target, ≥ 5 pt improvement target) → both narrowly missed. Trial is best framed as "data-diversity matters, but not enough on its own at 3 epochs."

In-mix eval (59.22%) underestimated FLEURS test (61.53%) by ~2 pts — the in-mix slice carries some FLEURS train data which the model technically saw. Worth noting for future trials: the FLEURS gap is a reliable +2 pt offset to the in-mix held-out.

### Local MPS replication (N=200, beams=5) — 2026-06-12

Re-benched all three checkpoints on the local Mac (MPS, fp32 — `m1_asr_hf.py` forces fp32 on MPS to avoid Whisper's known fp16-NaN behavior in `generate()`). This is the apples-to-apples run that motivates the M1 flip, using `make wer-hf M=<repo>` after [`scripts/eval_wer.py`](../../scripts/eval_wer.py) gained a `--model` flag earlier today.

| Model | Cloud CUDA fp16 | Local MPS fp32 | Δ (MPS − cloud) |
|---|---|---|---|
| v1 `devalade/whisper-large-v3-yoruba` | 65.92% | 69.24% | +3.32 |
| v2 `devalade/whisper-large-v3-yoruba-v2` | 66.09% | 68.54% | +2.45 |
| **v3** `devalade/whisper-large-v3-yoruba-v3` | **61.53%** | **63.71%** | **+2.18** |

Reads:
- **v3's win is protocol-independent.** v3 − v2 = −4.56 (cloud) vs −4.83 (MPS). Same direction, similar magnitude — the data-mix hypothesis is not a CUDA artifact.
- **v1 ↔ v2 ordering flips inside noise.** v2 was −0.17 worse than v1 on cloud and +0.70 better on MPS. At N=200 the ~1 pt confidence band easily covers this; the right read remains "v2 ≈ v1 on FLEURS," consistent with the single-speaker overfit diagnosis.
- **A consistent +2 to +3 pt MPS-vs-CUDA offset exists across all three models.** Probably fp32 vs fp16 generate-side numerics; not investigated further. Methodology should cite cloud numbers as the canonical figures and flag this offset as a known local-vs-cloud discrepancy.

## What worked

- **Demographic balancing as the diversity axis.** Holding LoRA + epoch budget constant and only varying the data mix gave a clean 4.5 pt FLEURS improvement — methodologically defensible.
- **Warm-starting from v2.** Saved one full fine-tune of compute and the model still consolidated a new shared representation across all 8 sources by epoch 2.
- **Anchoring with 5k Hidi-agili rows.** The Hidi-agili held-out regression I expected didn't bite — v3 doesn't catastrophically forget the TTS voice (still confirm via `make test-holdout` if needed).
- **Per-shard parquet glob in the loader (`data_files="*/yoruba_male_18-29.parquet"`).** Let us select demographic balance from chukypedro without trusting its unreliable `speaker_id` column.
- **The `setup_vast.sh` cache-volume pin.** A prior attempt died from a full root overlay; v2 of the script (this version) prevented the same failure.

## What didn't / what would I change

- **The bench script's first version was broken.** Original ran `M1_HF_MODEL="$model" python -m scripts.eval_wer …` thinking it would override the model, but `config.M1_HF_MODEL` is a hardcoded literal not an env var. Fixed by sed-editing `config.py` per iteration. _Resolved 2026-06-12: `scripts/eval_wer.py` now takes `--model`/`--processor`, surfaced as `make wer-hf M=<repo>`._
- **LR schedule was linear, not constant.** `_active.md`'s plan said "1e-5 constant" but the trainer defaulted to HF's linear warmup-then-decay. Outcome looks fine, but the doc and the code diverged. Either change the script to explicitly request constant, or update the plan to match what the default actually does.
- **Trial gate missed by margin.** The ≤ 60% target was set ambitiously; landing at 61.53% means "directionally right, quantitatively short." Future trial axes (data-mix + more epochs, or data-mix + LoRA r=64) are obvious next moves.
- **`speaker_id` column in chukypedro is useless.** Each parquet labels all its rows `speaker_id=1`. The demographic-shard partitioning saved us, but a future ASR dataset survey should call out "verify speaker labels are globally unique" as a pre-flight check.
- **Should have used `tee` from the start for the training log.** Re-attaching tmux is fine but per-step loss/grad-norm history would be more useful for the appendix if persisted to a file.

## Decision

✅ **Pushed to HF as `devalade/whisper-large-v3-yoruba-v3` (2026-06-11). `config.M1_HF_MODEL` flipped to v3 in `config.py` on 2026-06-12.** v1 and v2 ids preserved as commented-out lines in `config.py` for quick rollback / A/B.

The original gate (Hidi-agili held-out via `make test-holdout`, plus a manual A/B listen on `data/audio/eval_convo/` clips) was **not run before the flip** — thesis-submission day, and the local MPS replication (4.83 pt v3 − v2 margin, protocol-independent) was treated as sufficient signal that v3 is the right M1 default. Risks of skipping:

- **Hidi-agili regression unmeasured.** v3 anchors on 5k Hidi-agili rows so a hard regression is unlikely, but it is not measured. If a user reports the system "got worse on TTS-voice prompts," this is the first thing to check — `make test-holdout` against v3 is a 5-minute run.
- **Convo A/B unmeasured.** The 4.83 pt FLEURS win does not guarantee the same direction on spontaneous conversational speech, which is the actual deployment distribution. Worth running before any user-facing demo.

Both are listed as immediate-follow-up items below, not future work. If either flags a regression, roll back to v1 by un-commenting the v1 line in `config.py`.

The trial is recorded as a **marginal-but-shipped win**: directional validation of the data-diversity hypothesis, falling 1.5 pts short of the original quantitative gate (≤ 60% FLEURS) but the best M1 backend on every available signal. Defensible thesis material as a "v1 → v2 → v3" arc that shows finding and fixing a real failure mode (single-speaker overfit), more compelling than three monotonic improvements would have been.

### Hidi-agili distribution probe (2026-06-12)

**Goal:** approximate the missing held-out check — confirm v3 hasn't catastrophically forgotten the Hidi-agili TTS voice it was anchored on.

**Method:** [`scripts/hidi_probe.py`](../../scripts/hidi_probe.py) loads `Hidi-agili/yoruba_tts_dataset`, applies the same `shuffle(seed=42)` the trainer used, and runs M1 on rows 5000-5024 — i.e. the first 25 rows v3's training cap **excluded**. Same dataset, same voice, but v3 did not see these specific rows. Same diacritic-stripped WER normalization as `eval_wer.py`.

**Result:**

| Model | Probe WER (N=25, seed=42, skip=5000) | FLEURS (MPS) | Read |
|---|---|---|---|
| v3 `devalade/whisper-large-v3-yoruba-v3` | **50.27%** | 63.71% | Hidi-agili lower than FLEURS as expected (1 voice vs 200+) → anchor held |

Per-sample log: [`logs/hidi_probe_v3.jsonl`](../../logs/hidi_probe_v3.jsonl).

**Caveats:**
- **No v1/v2 comparison.** v1 trained on the entire Hidi-agili dataset (old `FT_DATASETS = ["Hidi-agili/..."]` path before the v3 mix loader), so rows 5000-5024 of `shuffle(seed=42)` were inside v1's training set. A v1 number on these rows would be in-distribution, not held-out — apples-to-oranges. The probe stands on its own as a v3 sanity check, not as a v1↔v3 comparison.
- **N=25 is small.** Three outliers (samples 0, 9, 14) on very short utterances inflate the aggregate; the median sample sits ~33-50%. A larger N would tighten the confidence band; submission timing didn't allow it.
- **Not a true held-out.** A true held-out requires re-running training with `--holdout-n` and scp'ing the WAVs back. This probe is the next-best approximation — same dataset, same voice, demonstrably unseen rows, but produced post-hoc rather than carved before training.

**Conclusion:** Anchor held. 50.27% lands in the "v3 reads the TTS voice fine" band (~30-60% expected for single-voice Whisper performance on the FLEURS protocol). No rollback signal. The convo A/B against `data/audio/eval_convo/` is the remaining gate.

## Next trial candidates

In rough priority order:

1. **v4 = v3 data-mix + 5 epochs.** Same mix, longer training to see if more epochs close the remaining gap to ≤ 60%. Cheapest experiment.
2. **v4 = v3 data-mix + LoRA r=64.** More capacity, same data and epochs. Tests whether r=32 was the limiter.
3. **v4 = v3 + code-switched data.** Add Nigerian English / YO-EN code-switched clips. Errors qualitatively concentrated here.
4. **v4 = full fine-tune of small/medium Whisper on v3 data.** Tests whether LoRA on large was actually the right capacity trade.
