**Goal:** Train a new Whisper-large-v3 LoRA fine-tune with the runbook recipe (3 epochs, BATCH=12, bf16) on a *verified* CUDA+bf16 path, pushed as a separate HF repo so the v1 baseline survives for A/B.

Best metric: 0.49211884502720044 (epoch 3, the last). 45 train-loss log points total (every 25 steps, 15 per epoch). Extracted from local `trainer_state.json`.

**Nuance for the more-epochs decision:** epoch 3 train loss is nearly flat (0.884 → 0.872) — the model has effectively fitted the training distribution. Eval loss + WER are still dropping, so generalization is still improving. But the typical overfit signature (train loss keeps falling while eval stalls or rises) is **about to start**. The 5-epoch follow-up should watch for it: if train loss drops below ~0.85 at epoch 4 while eval WER plateaus or rises, that's the stop signal.

## Important caveat

The **49.21% eval WER above is on the held-out 5% of `Hidi-agili/yoruba_tts_dataset` (~451 samples), not on FLEURS**. It's only comparable across runs trained on this dataset with the same eval split — not against the v1 numbers, the prior Rafat baseline, or the base whisper-large-v3 zero-shot. The FLEURS + convo tables above are the ones that go in the thesis.

## What worked

- After fixing the CPU-torch wheel issue (see "what didn't"), the runbook recipe ran cleanly start to finish: 73 min training + 1 min merge/push on a 5090.
- `BATCH=12` fits comfortably in 32 GB VRAM with gradient checkpointing — confirms the runbook recommendation against the actual hardware.
- Pushing under a `-v2` suffix preserved the v1 baseline for A/B, per the runbook discipline.

## What didn't / what would I change

- **The CPU-torch wheel trap re-bit us.** Fresh Vast box, `pip install -r requirements.txt` quietly installed the CPU build of torch, and `make finetune` started training on the 32-core Threadripper at 231 s/step (ETA 120 hours). The script warns on no-CUDA but continues; that warning needs to be a hard fail. See [`fine-tuning-runbook.md`](../fine-tuning-runbook.md) — the preflight step needs strengthening, and `requirements.txt` should pin the CUDA wheel.
- **Three `runs/` subdirs** in TensorBoard logs from the launch/abort cycle. The `Jun09_10-20-47_*` dir is the only meaningful one; the other two are CPU-broken attempts. Worth dropping the first two before scp-ing back.
- **Hypothesis underexecuted.** `_active.md` was seeded for a 5-epoch trial; this run did the default 3 epochs because the relaunch after the CUDA fix used the runbook command (`EPOCHS=3 BATCH=12`) rather than `EPOCHS=5`. The data we got (monotone loss + WER through epoch 3) supports — but does not test — the more-epochs hypothesis. The next trial should be the actual 5-epoch run.
