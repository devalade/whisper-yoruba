# Project conventions

## Documentation

**Document everything in `docs/`.** Whenever a non-trivial decision is made, a bug is hit and fixed, a runbook is established, or a piece of context would be useful to a future contributor — write it down in `docs/` as part of the same change.

- One topic per file, kebab-case names (e.g. `docs/fine-tuning-runbook.md`, `docs/vast-ai-setup.md`).
- Keep entries scannable: lead with the problem or goal, then the answer.
- Update existing docs rather than creating near-duplicates.
- README.md stays as the high-level pitch + quickstart; deeper material lives in `docs/`.
